## 修复清单

### 写锁与并发（4 条）

1. **`backend/services/asset_service.py` 持有独立 `_WRITE_LOCK` 实例**
   - `AssetService.add_asset` / `update_asset` / `delete_asset` 自有 `threading.Lock`，与 `collection_service._WRITE_LOCK` 是两个对象
   - 高并发下两边分别加锁，依然能并发写同一张 SQLite 表 → 资金写端点与采集清理互不感知
   - **修复**：删除本地 `threading.Lock()`，改为从 `backend.services._write_lock` 导入共享 `_WRITE_LOCK`
   - 涉及文件：[`backend/services/asset_service.py:9`](../../backend/services/asset_service.py)、[`backend/services/_write_lock.py`](../../backend/services/_write_lock.py)（新建）

2. **`backend/services/_collection/_quotes.py` / `_daily_close.py` 写 `run_logs` 未持共享写锁**
   - `collect_quotes` / `collect_daily_close` 收尾直接 `get_db()` 写审计行，绕过项目级"所有 SQLite 写必须持锁"硬约束
   - **修复**：在 `backend/services/_collection/_helpers.py` 新增 `_write_run_log_locked()` 集中 helper，`_with_run_log()` 装饰器与 quote/daily_close mixin 统一调用
   - 涉及文件：[`_helpers.py:43-66`](../../backend/services/_collection/_helpers.py)、[`_quotes.py:8`](../../backend/services/_collection/_quotes.py)、[`_daily_close.py:9`](../../backend/services/_collection/_daily_close.py)

3. **`backend/scheduler/jobs.py::_run_cleanup` 缺少 `run_logs` 审计**
   - 清理任务跑完既没有 `started_at/finished_at`，也没有 `affected_assets`，UI 看不出历史执行
   - **修复**：清理 + 审计行写入全部在共享写锁内完成，`status = "success" / "failure"`，`affected_assets` 取实际删除行数；外层 `try/except` 兜底后用 `_write_neo_health_log_sync()` 记录崩溃
   - 涉及文件：[`backend/scheduler/jobs.py`](../../backend/scheduler/jobs.py)

4. **`_collection/_core.py` 仍导出 `_WRITE_LOCK`，导致 mixin 锁源多源化**
   - 重构后 `_core` 不再持有锁，但旧导入 `from backend.services._collection._core import _WRITE_LOCK` 仍可解析
   - **修复**：从 `_core.py` 移除锁导出，引用统一收口到 `_write_lock.py`；`collection_service.py` 再 re-export 一份保持 `from backend.services.collection_service import _WRITE_LOCK` 兼容

### 采集幂等与 raw 审计（1 条）

5. **`backend/services/news_service.py::collect_news` 无 URL 新闻去重缺失 + 跳过 `raw_data`**
   - `if url: existing_urls.add(url)` 之前直接 `continue`，导致：
     - 同源同标题无链接新闻**无限重复入库**（每次采集都算"新"）
     - 即使成功插入，`raw_data` 也只在 `url` 非空时落库 → 审计断档
   - **修复**：构造稳定去重键 `(source, normalized_title, published_at)`，跨批 + 跨库去重；`raw_data` 改为"插入成功即落库"，不再依赖 `url`
   - 涉及文件：[`news_service.py:1-260`](../../backend/services/news_service.py)

### 前端导航契约（2 条）

6. **`frontend/src/pages/AssetDetail/index.tsx` 不读 `?assetId=` 查询参数**
   - Command Palette 已生成 `?assetId=...`，但详情页 `useState<number | null>(null)` 始终从空起步
   - 表现：从命令面板跳转后页面渲染"暂无数据"，用户得手动下拉选标的
   - **修复**：`useSearchParams` 同步 `?assetId=`，本地 state 改由 URL 派生；切换标的时 `setSearchParams({ assetId: ... })` 反向写回 URL
   - 涉及文件：[`AssetDetail/index.tsx:1-50`](../../frontend/src/pages/AssetDetail/index.tsx)

7. **`frontend/src/pages/NewsList/index.tsx` related symbol 跳转未注册路由**
   - 旧实现 `navigate(\`/asset-detail/${symbol}\`)` 命中不存在的路由
   - **修复**：先 `GET /api/v1/assets?search=<symbol>` 解析出 `assetId`，再 `navigate(\`/asset-detail?assetId=<id>\`)`；解析失败用 `message.warning` 提示用户
   - 涉及文件：[`NewsList/index.tsx:1-220`](../../frontend/src/pages/NewsList/index.tsx)

### 文档与契约同步（5 条）

8. **`docs/api/settings.md` `interval` 字段误为字符串 `"15m"`**
   - `IntervalTrigger(minutes=...)` 实际接收 `int` 分钟数，旧文档误导为字符串
   - **修复**：示例与类型表统一改为 `int`（如 `15` / `60`），加 `1 ≤ interval ≤ 1440` 范围说明

9. **`docs/api.md` / `docs/api/news-reports-tasks.md` `run_logs.status` 多列出 `failed` / `running`**
   - 实现只写 `success` / `failure`，文档漂移让 UI 永远查不到 `failed` 历史
   - **修复**：文档统一为 `success / failure`，删除 `running`（任务短暂、无中间态可持久化）

10. **`docs/api/assets.md` 资产写端点声明要求 `X-API-Key`，实际未鉴权**
    - 旧 `verify_api_key` 已对 `/assets/*` 开放但文档未跟进
    - **修复**：状态码表移除 `401`；注明"当前 assets 写端点不要求 API Key"；同步 `docs/api.md` 鉴权范围

11. **`docs/prd.md` / `docs/features.md` 搜索端点误为 `POST /assets/search`**
    - 实际为 `GET /assets/search?keyword=...`
    - **修复**：两处统一改为 `GET`，并加 `restful-api-design` 技能注释（GET 用于纯查询）

12. **`docs/architecture.md` 鉴权范围表 / 路由表 `assets` 列需同步**
    - 与 docs/api/assets.md 改动一致
    - **修复**：路由表"是否鉴权"列从"是"改为"否"，文字说明补一笔排除 `/assets/*`
