# MarketLens 产品需求文档 (PRD)

> 版本: 1.2 | 日期: 2026-06-05 | 状态: MVP 已完成（除 AI 问答）

---

## 1. 产品愿景

**做一个个人投资者真正能用起来的 AI 研究助理** — 不需要盯盘、不需要手动翻财报、不需要在各个 App 之间切来切去。用户只需维护一份自己关注的标的清单，系统自动采集数据、沉淀历史、生成带证据的 AI 分析报告，让投资决策有据可依。

### 1.1 一句话定位

> 本地优先、证据驱动的 AI 金融研究助理，帮你从数据噪声中提炼可追溯的投资洞察。

### 1.2 核心价值主张

| 维度 | 用户痛点 | MarketLens 方案 |
|---|---|---|
| 信息过载 | 财经 App 推送轰炸，重要信息被淹没 | 只看你追踪的标的，AI 摘要提炼关键变化 |
| 数据碎片化 | 行情/财报/新闻分散在不同平台 | 统一采集、统一存储、关联查询 |
| AI 幻觉 | ChatGPT 编造股价和财务数据 | 证据驱动：AI 只基于本地采集的真实数据输出 |
| 可追溯性 | "上次为什么买这只？"想不起来 | 每份 AI 报告列出引用的数据源和采集时间 |
| 隐私/成本 | 投资组合数据上云不放心 | 全部本地运行，SQLite + 本地 Python，数据不上传 |

## 2. 目标用户

### 2.1 主要用户画像

| 画像 | 描述 | 核心需求 |
|---|---|---|
| **独立个人投资者** | 有自己关注的 10-50 只股票/ETF，业余时间做研究 | 自动采集 + AI 摘要，节省手动搜集数据的时间 |
| **财经爱好者/学生** | 学习投资分析，需要系统化的数据和分析框架 | 结构化的财务/技术指标 + 可理解的 AI 解释 |
| **小型研究团队** | 2-3 人协作，关注特定行业或板块 | 多标的批量追踪，新闻情绪汇总 |

### 2.2 不服务的人群（MVP 阶段）

- 量化交易者（需要毫秒级行情和回测框架）
- 机构投资者（需要合规审计、多用户权限）
- 纯技术分析派（只需要 K 线图，不需要 AI 分析）

## 3. 用户场景与故事

### 3.1 核心场景

**场景 1：每日复盘**

> 小王每天下班后打开 MarketLens，查看 AI 为他的 15 只追踪标的生成的每日报告。报告告诉他：腾讯短期趋势震荡但资金面改善，比亚迪财报超预期但技术面有高位风险。每一条结论都标注了数据来源，他可以点进去看原始数据验证。

**场景 2：新闻轰炸中的信号提取**

> 某天新能源板块出了 30 条新闻，小王不可能全看。MarketLens 的新闻采集按他的追踪标的自动筛选关联新闻，AI 报告汇总了情绪倾向："近 3 日宁德时代相关新闻 12 条，正面 8 条、中性 3 条、负面 1 条，主要集中在海外订单突破。"

**场景 3：决策回顾**

> 小王上个月买入了小米，现在想回顾当初的判断依据。他打开小米的历史 AI 报告，看到 4 月 15 日的报告建议 "watch→buy"，理由包括"MA20 上穿 MA60、Q1 财报超预期、主力资金连续 5 日净流入"。这让他对这轮操作的逻辑更有信心。

**场景 4：标的筛选**

> 小王想找几只高股息的银行股加入追踪。他用搜索功能输入"银行 股息率"，系统返回匹配标的，他选了 3 只加入追踪列表。第二天开始，系统自动为这 3 只新标采集数据和生成报告。

**场景 5：跨平台持仓管理**

> 小王在富途持有腾讯、华泰持有比亚迪和茅台，之前每次想看整体盈亏都得打开两个 App 分别算。现在他在 MarketLens 里建了“富途”和“华泰”两个账户，把每笔买入卖出交易手动录入。系统自动汇总：当前总持仓市值、每只标的的浮动盈亏、各账户的已实现收益。他看一眼就知道自己在腾讯上赚了 15%、比亚迪还亏着 8%，不用再到处翻了。

**场景 6：交易复盘**

> 月底小王想复盘这个月的操作。他在交易列表里筛选本月已卖出的记录，看到小米这笔 4 月 18 日买入、5 月 10 日卖出的交易实现了 12% 的收益，但宁德时代同期买入却在 5 月 15 日止损卖出亏了 7%。结合 AI 报告回顾，他发现宁德时代当时的报告已经提示了“高位死叉风险”，当时没重视。这个月他调整了策略，优先参考 AI 的风险提示。
**场景 7：深度个股研究**

> 小王最近关注比亚迪，想知道筹码分布和业绩预期。他打开比亚迪的股东结构页，看到十大股东里机构持仓比例在上升、股东人数近两季度在减少——筹码在集中。切到业绩预告页，显示最新预告为"预增"，利润下限 400 亿、上限 450 亿，同比增幅 20%~35%。他又看了分红历史，近三年每股分红稳步增长。结合 AI 报告的 K 线和资金流分析，他对当前价位更有信心了——这比打开好几个 App 翻数据高效太多了。

### 4.2 功能详细说明

#### FR-1: 标的管理

| 需求项 | 说明 |
|---|---|
| 添加标的 | 输入股票代码（如 hk00700），系统自动补全名称和市场 |
| 资产类型 | 支持：股票、ETF、指数、期货（MVP）；预留：外汇、商品 |
| 市场 | 支持：A 股（sh/sz）、港股（hk）、美股（us）、期货（fut） |
| 标签 | 用户自定义标签（如"新能源""高股息""观察中"） |
| 状态 | 启用 = 参与自动采集和分析；停用 = 保留数据但停止更新 |

#### FR-2: 投资组合管理

| 需求项 | 说明 |
|---|---|
| 账户管理 | 用户可创建多个交易账户（如“富途”、“华泰”），每个账户有名称、券商、默认币种 |
| 交易录入 | 支持买入、卖出、分红、拆股四种交易类型；必填字段：标的代码、数量、价格、日期；可选字段：手续费、币种、备注 |
| 持仓汇总 | 自动按标的聚合计算：持仓量、均价、当前市值、浮动盈亏（基于最新行情）、浮动盈亏率 |
| 盈亏分析 | 已实现盈亏（卖出交易汇总）：总盈亏金额、收益率；未实现盈亏（持仓浮动） |
| 交易历史 | 按账户、标的、日期范围、交易类型筛选；支持编辑和删除（软删除，保留审计痕迹） |
| 费率支持 | 手续费字段按交易记录级存储，支持百分比费率或固定金额 |

**数据模型：**

- accounts 表：id, name, broker, currency, notes, created_at
- transactions 表：id, account_id, symbol, type(buy/sell/dividend/split), quantity, price, fee, currency, trade_date, notes, created_at
- positions 视图：symbol, account_id, total_qty, avg_cost, market_value, unrealized_pnl  — 实时计算

**盈亏计算规则：**
- 均价采用加权平均法（买入时重新计算，卖出时不改变均价）
- 浮动盈亏 = (当前市价 - 均价) × 持仓量
- 已实现盈亏 = 卖出金额 - 卖出数量 × 卖出时均价 - 卖出手续费
- 分红和拆股仅调整持仓量/均价，不直接产生盈亏

#### FR-3: 数据采集

| 需求项 | 说明 |
|---|---|
| 行情 | 最新价、涨跌幅、涨跌额、成交量、振幅、换手率 |
| K 线 | 日线：开、高、低、收、成交量 |
| 财务 | 最新一期：营收、净利润、每股收益、净资产收益率 |
| 资金流 | 主力净流入、超大单/大单/中单/小单净流入 |
| 技术指标 | MA5/MA10/MA20/MA60、MACD(DIF/DEA/柱)、RSI、布林带 |
| 新闻 | 标题、来源、发布时间、链接、正文/摘要、关联标的 |

#### FR-4: AI 分析

| 需求项 | 说明 |
|---|---|
| 输出格式 | 固定 JSON：symbol, action, confidence, risk_level, summary, reasons, key_risks, data_used |
| 动作建议 | buy（买入）/ sell（卖出）/ watch（观望）/ avoid（回避） |
| 证据引用 | data_used 字段列出每个引用的数据源、类型和采集时间 |
| 置信度 | 0-1 浮点数，反映信号强度和证据充分程度 |
| 风险等级 | low / medium / high |

#### FR-5: 定时调度

| 任务 | 频率 | 说明 |
|---|---|---|
| 行情采集 | 15 分钟 | 仅交易时段有意义，非交易时段自动跳过 |
| 日收盘采集 | 交易日 16:00 | K 线、资金流、技术指标（日级别数据） |
| 新闻采集 | 60 分钟 | 增量采集，去重 |
| AI 报告 | 每日 20:00 | 基于当日收盘数据生成 |

#### FR-6: 数据查看与交互

| 需求项 | 说明 |
|---|---|
| 标的详情 | 聚合展示：最新行情 + K 线摘要 + 财务关键指标 + 资金流向趋势 |
| 新闻列表 | 支持按标的、日期范围筛选，显示情绪标签 |
| AI 报告 | 卡片式展示：动作建议 + 置信度 + 多空理由 + 风险提示 |
| 任务状态 | 显示最近一次各任务的执行时间、状态（成功/失败）、耗时 |

## 5. 非功能需求

### 5.1 性能

| 指标 | 目标值 | 说明 |
|---|---|---|
| 单标的行情采集 | < 3 秒 | subprocess 调用 + 解析 |
| 全量标的采集（20 只） | < 30 秒 | `asyncio.gather` 并发采集，逐个标的并行 |
| API 响应时间 | < 500ms | 简单查询（单表） |
| AI 报告生成（20 只） | < 60 秒 | 规则引擎 + 证据包并行组装 |
| 数据库大小（1 年数据） | < 500MB | 20 只标的，日级别数据 |

### 5.2 可靠性

| 指标 | 目标值 |
|---|---|
| 数据源单点故障 | 不导致系统崩溃，其他源正常采集 |
| 单标的采集失败 | 不影响同一批次其他标的 |
| 调度任务异常 | 下次调度正常执行，记录失败日志 |
| 数据库损坏 | 支持从原始数据重建（raw_data 表） |

### 5.3 可用性

| 指标 | 目标值 |
|---|---|
| 安装复杂度 | 3 条命令完成环境搭建 |
| 学习成本 | 新用户 5 分钟内完成首个标的新增和查看 |
| 界面语言 | 中文 |
| 文档语言 | 中文 |

### 5.4 安全性

| 要求 | 说明 |
|---|---|
| 数据本地化 | 所有数据存储于本地 SQLite，不上传任何云端 |
| 无外部账号依赖 | 数据源为公开接口，不强制注册；NeoData 凭证本地缓存可选 |
| 配置文件安全 | config.yaml 中的敏感字段支持环境变量替代 |
| 写端点鉴权 | 9 个写端点需要 `X-API-Key` 头：POST/PATCH/DELETE on `/assets`、`/accounts`、`/transactions`；POST on `/reports/generate`；POST on `/neodata/token`；POST on `/tasks/trigger/{name}` |
| 默认 API Key | 本地默认 `marketlens-local`；生产环境必须通过环境变量 `MARKETLENS_API_KEY` 或 `config.security.api_key` 覆盖，否则启动日志会发出 warning |
| Security Headers | 5 个安全响应头由 `SecurityHeadersMiddleware` 统一注入：`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: no-referrer`、`Strict-Transport-Security`、`Content-Security-Policy`（宽松以兼容 Swagger UI） |

### 5.5 可扩展性

| 要求 | 说明 |
|---|---|
| 新增数据源 | 实现 Provider 接口 + config.yaml 注册即可，无需改核心逻辑 |
| 新增资产类型 | 扩展 asset_type 枚举，Provider 按类型路由 |
| AI 引擎替换 | AIAnalyzer 接口不变，内部可从规则引擎替换为 LLM 调用 |
| 前端替换 | Streamlit 可替换为其他框架，API 层不变 |

## 6. 约束与假设

### 6.1 约束

| 约束 | 说明 |
|---|---|
| 仅本地运行 | 不做 SaaS、不做多用户服务端部署 |
| 仅 SQLite | 不做 PostgreSQL/MySQL 迁移，不引入其他数据库 |
| 单用户 | 无用户认证、无权限管理、无多租户 |
| 无自动交易 | 不接券商 API，不下单，AI 建议仅供参考 |
| Node.js 依赖 | WeStock 数据源需 Node.js ≥ v18 运行 CLI |
| 仅交易日数据 | 非交易日跳过行情采集，K 线数据不含非交易日 |

### 6.2 假设

| 假设 | 说明 |
|---|---|
| 用户有基础 Python 环境 | 假设用户能运行 pip/uv 命令 |
| 网络可用 | 采集依赖外部数据源（新浪/WeStock/RSS），需联网 |
| 单机运行 | 不涉及分布式、不涉及容器化部署（MVP） |
| 数据源持续可用 | 依赖的公开数据源保持现有接口格式 |

## 7. 不做的事（MVP 阶段明确排除）

| 排除项 | 原因 |
|---|---|
| 实时推送/通知 | MVP 聚焦数据沉淀和报告，不做消息推送 |
| 回测/策略引擎 | 不做量化回测，不做交易策略 |
| 移动端 App | MVP 仅桌面 Web UI（Streamlit） |
| 多语言 | 仅中文 |
| 社区/分享功能 | 纯本地工具，无社交功能 |
| 盘中实时 AI 分析 | AI 每日收盘后运行一次 |
| 外汇/加密货币 | 优先支持股票、ETF、指数、期货 |

## 8. 验收标准

### 8.1 MVP 验收清单

- [x] 用户可以添加至少 5 个追踪标的（包含 A 股、港股、美股、期货）
- [x] 系统自动按配置频率采集行情、K 线、资金流、技术指标、新闻
- [x] 所有采集数据保存历史，可回溯查看
- [x] 每日自动为每个活跃标的生成 AI 分析报告
- [x] AI 报告包含 data_used 字段，列出引用数据源和采集时间
- [x] 任一数据源失败不导致系统崩溃
- [x] 任一标的采集失败不影响其他标的
- [x] 用户可在 UI 中查看：追踪列表、标的详情、新闻、AI 报告、任务状态、**持仓总览、盈亏分析**
- [x] 用户可创建多个交易账户，区分不同平台持仓
- [x] 用户可手动录入买入/卖出交易（含手续费、币种），系统自动计算均价和盈亏
- [x] 持仓页实时汇总各标的的持仓量、均价、浮动盈亏、已实现盈亏
- [x] 交易记录支持编辑和删除
- [ ] AI 问答可基于本地数据回答用户问题（不编造信息）
- [x] 用户可查看任一标的的分时走势数据
- [x] 用户可查看任一标的的十大股东和股东人数变化
- [x] 用户可查看任一标的的最新业绩预告
- [x] 用户可查看任一标的的历史分红记录
- [x] 投资组合：交易历史与已实现盈亏汇总均支持分页（`page` / `page_size` 参数）
- [x] 投资组合：账户与交易均使用软删除（`deleted_at` 标记）保留审计痕迹
- [x] 投资组合：持仓总览、已实现盈亏支持按账户 ID 跨账户汇总
