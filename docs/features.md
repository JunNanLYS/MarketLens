```
MarketLens
├── 🏷️  标的管理     ← 追踪什么
├── 💼 投资组合     ← 持仓盈亏
├── 📡 数据采集      ← 行情/K线/财务/资金流/技术/新闻/分时/股东/预告/分红
├── 🧠 AI 分析       ← 证据驱动的智能研判
├── ⏰ 定时调度      ← 无人值守自动运行
├── 📊 数据查看      ← 可视化消费数据
├── ⚙️  系统配置      ← 按需调整行为
└── 📋 任务监控      ← 了解系统运行状态
```

## 3. 功能详细规格

### 3.1 标的管理

#### F-01: 添加追踪标的

| 属性 | 内容 |
|---|---|
| **用户故事** | 作为投资者，我想要添加我关注的股票到追踪列表，以便系统自动为我采集数据 |
| **触发方式** | UI 表单输入 + API `POST /assets` |
| **输入** | 股票代码（必填）、名称（自动补全）、市场（自动识别）、资产类型（默认：股票）、标签（可选，逗号分隔）、备注（可选） |
| **处理逻辑** | 1. 校验代码格式（按市场验证） 2. 调用 Provider.search() 确认标的存在 3. 检查是否已在追踪列表（防重复） 4. 入库，默认 enabled=true |
| **输出** | 创建成功的标的对象（含 ID、创建时间） |
| **异常** | 代码无效 → 400 "无法识别该代码"；重复添加 → 409 "该标的已在追踪列表" |
| **依赖** | 至少一个启用的数据源 Provider |

**验收标准：**
- [ ] 支持 A 股（sh/sz）、港股（hk）、美股（us）、期货（fut）代码格式
- [ ] 代码无效时给出明确提示
- [ ] 重复添加同一代码时拒绝并提示
- [ ] 添加成功后自动出现在追踪列表

---

#### F-02: 查看追踪列表

| 属性 | 内容 |
|---|---|
| **用户故事** | 作为投资者，我想要查看所有追踪标的，按条件筛选，以便快速找到目标 |
| **触发方式** | UI 页面加载 + API `GET /assets` |
| **输入** | 筛选条件（可选）：`enabled`、`market`、`asset_type`、`tag` |
| **处理逻辑** | 从 tracked_assets 表查询，支持多条件组合筛选，按创建时间倒序排列 |
| **输出** | 标的列表，每项显示：代码、名称、市场、类型、标签、状态、最新行情（若有） |
| **依赖** | tracked_assets 表 |

**验收标准：**
- [ ] 默认显示全部启用的标的
- [ ] 可按市场（hk/us/sh/sz/fut）筛选
- [ ] 可按资产类型（股票/ETF/指数/期货）筛选
- [ ] 可按标签筛选
- [ ] 已停用的标的默认隐藏，可切换显示

---

#### F-03: 启用/停用追踪

| 属性 | 内容 |
|---|---|
| **用户故事** | 作为投资者，我想要临时停用某个标的的追踪，以便减少不必要的数据采集 |
| **触发方式** | UI 开关按钮 + API `PATCH /assets/{id}` |
| **输入** | 标的 ID、`enabled: true/false` |
| **处理逻辑** | 更新 tracked_assets 表的 enabled 字段。enabled=false 的标的不会出现在调度采集任务的目标列表中 |
| **输出** | 更新后的标的对象 |
| **异常** | 标的不存在 → 404 |
| **依赖** | tracked_assets 表 |

**验收标准：**
- [ ] 停用后，调度任务不再采集该标的数据
- [ ] 停用后，历史数据保留不删除
- [ ] 重新启用后，恢复采集和 AI 分析

---

#### F-04: 编辑标的信息

| 属性 | 内容 |
|---|---|
| **用户故事** | 作为投资者，我想要修改标的的标签和备注，以便更好地分类和记录 |
| **触发方式** | UI 编辑表单 + API `PATCH /assets/{id}` |
| **输入** | 标的 ID、可修改字段：`tags`、`notes` |
| **处理逻辑** | 部分更新，只更新提交的字段 |
| **输出** | 更新后的标的对象 |
| **异常** | 标的不存在 → 404 |

---

#### F-05: 删除标的

| 属性 | 内容 |
|---|---|
| **用户故事** | 作为投资者，我想要从追踪列表中删除不再关注的标的 |
| **触发方式** | UI 删除按钮（需确认） + API `DELETE /assets/{id}` |
| **处理逻辑** | 从 tracked_assets 表删除。关联数据（行情/K 线/新闻/AI 报告）保留不级联删除（历史数据可追溯） |
| **输出** | 204 No Content |
| **异常** | 标的不存在 → 404 |

**验收标准：**
- [ ] 删除前弹出确认提示
- [ ] 删除后从追踪列表消失
- [ ] 历史数据保留不丢失

---

#### F-06: 搜索标的

| 属性 | 内容 |
|---|---|
| **用户故事** | 作为投资者，我想要搜索不在追踪列表中的标的，以便发现新的投资机会 |
| **触发方式** | UI 搜索框 + API `POST /assets/search` |
| **输入** | 关键词（代码/名称/行业） |
| **处理逻辑** | 调用 Provider.search()，返回匹配的标的列表。按优先级使用多个数据源的搜索结果 |
| **输出** | 候选标的列表（代码、名称、市场、类型、最新价） |
| **依赖** | 至少一个启用的数据源 Provider |

### 3.2 投资组合管理

#### F-29: 创建交易账户

| 属性 | 内容 |
|---|---|
| **用户故事** | 作为投资者，我想要创建多个交易账户（如富途、华泰），以便区分不同平台的持仓 |
| **触发方式** | UI 表单 + API POST /accounts |
| **输入** | 账户名称（必填）、券商（可选）、默认币种（默认CNY）、备注（可选） |
| **处理逻辑** | 校验名称非空且不重复 → 写入 accounts 表 |
| **输出** | 创建成功的账户对象 |
| **异常** | 同名账户 → 409 |

#### F-30: 编辑/删除账户

| 属性 | 内容 |
|---|---|
| **用户故事** | 作为投资者，我想要修改或删除不再使用的交易账户 |
| **触发方式** | UI 按钮 + API PATCH /accounts/{id} / DELETE /accounts/{id} |
| **输入** | 账户 ID + 可修改字段 |
| **处理逻辑** | 删除账户时若有关联交易则提示确认（软删除） |
| **异常** | 账户不存在 → 404 |

#### F-31: 录入买入交易

| 属性 | 内容 |
|---|---|
| **用户故事** | 作为投资者，我想要手动录入每一笔买入交易，以便记录真实持仓成本 |
| **触发方式** | UI 表单 + API POST /transactions |
| **输入** | 账户（必选）、标的代码（必填）、数量（必填）、价格（必填）、交易日期（必填，默认当日）、手续费（可选）、币种（默认CNY）、备注（可选） |
| **处理逻辑** | 1. 校验标的存在于追踪列表（若无则提示先添加） 2. 写入 transactions 表 (type=buy) 3. 重新计算该标的均价（加权平均） |
| **输出** | 创建成功的交易记录 |

**验收标准：**
- [ ] 买入后均价按加权平均正确更新
- [ ] 支持同一标的多次买入（分批建仓）
- [ ] 小数数量支持（ETF 等）

#### F-32: 录入卖出交易

| 属性 | 内容 |
|---|---|
| **用户故事** | 作为投资者，我想要记录每一笔卖出交易，以便计算实际盈亏 |
| **触发方式** | UI 表单 + API POST /transactions |
| **输入** | 同买入，type=sell。需验证卖出数量不超过当前持仓 |
| **处理逻辑** | 1. 校验持仓足够 2. 写入 transactions 表 (type=sell) 3. 计算已实现盈亏 = 卖出金额 - 卖出数量 × 均价 - 手续费。卖出不改变持仓均价 |
| **异常** | 卖出数量超过持仓 → 400 |
| **验收标准** | 卖出后持仓量正确减少，已实现盈亏正确计算 |

#### F-33: 录入分红/拆股

| 属性 | 内容 |
|---|---|
| **用户故事** | 作为投资者，我想要记录分红和拆股事件，以便持仓数据保持准确 |
| **触发方式** | UI 表单 + API POST /transactions |
| **输入** | type=dividend(分红) 或 split(拆股)，分红填金额，拆股填比例（如 2:1 填 2） |
| **处理逻辑** | 分红：增加现金记录，不影响持仓量；拆股：按比例调整持仓量和均价 |

#### F-34: 持仓总览

| 属性 | 内容 |
|---|---|
| **用户故事** | 作为投资者，我想要在一个页面上看到所有账户的全部持仓 |

| **输入** | 筛选条件（可选）：account_id、market |
| **处理逻辑** | 实时聚合所有未完全卖出的标的：持仓量、均价、最新行情价、市值、浮动盈亏、浮动盈亏率。按账户或全账户汇总展示 |
| **输出** | 持仓列表 + 汇总统计（总市值、总浮动盈亏） |
| **依赖** | transactions 表 + market_quotes 表 |

#### F-35: 浮动盈亏查看

#### F-36: 已实现盈亏查看

### 3.3 数据采集

#### F-07: 实时行情采集

| 属性 | 内容 |
|---|---|
| **用户故事** | 作为投资者，我想要自动获取追踪标的的实时行情，不用手动刷新 |
| **触发方式** | 定时（每 15 分钟）+ 手动触发 API |
| **输入** | 所有 enabled=true 的标的代码列表 |
| **处理逻辑** | 1. 获取活跃标的列表 2. 按市场分组，调用对应 Provider.quote() 3. 保存 raw_json 到 raw_data 表 4. 标准化后写入 market_quotes 表 5. 写入 run_logs |
| **输出** | run_logs 记录（成功数/失败数/耗时） |
| **异常** | Provider 超时 → 记录日志，跳过；单标的失败 → 跳过，继续下一个 |
| **依赖** | WeStockProvider / SinaProvider |

**采集字段：** 最新价、开盘价、最高价、最低价、昨收价、涨跌幅、涨跌额、成交量、成交额、振幅、换手率、52 周最高/最低

---

#### F-08: 日 K 线采集

| 属性 | 内容 |
|---|---|
| **用户故事** | 作为投资者，我想要自动获取追踪标的的历史 K 线，以便分析趋势 |
| **触发方式** | 定时（交易日 16:00）+ 手动触发 API |
| **输入** | 所有 enabled=true 的标的代码列表 |
| **处理逻辑** | 1. 调用 Provider.kline() 获取最近 N 个交易日日 K 2. 与已有数据比对，仅插入新交易日 3. 保存标准化数据到 kline_daily 表 |
| **输出** | 新增 K 线条数 |
| **幂等** | INSERT OR IGNORE（按 symbol+date 唯一约束防重复） |

#### F-12: 新闻采集与关联

| 属性 | 内容 |
|---|---|
| **用户故事** | 作为投资者，我想要自动获取与追踪标的相关的新闻，以便及时了解市场动态 |

| **输入** | 所有 enabled=true 的标的 |

**验收标准：**
- [ ] 同一 URL 的新闻不重复入库
- [ ] 一条新闻可关联多个标的
- [ ] NeoData 不可用时自动降级到 RSS，不影响主流程

### 3.4 AI 分析

#### F-13: 证据包组装

|---|---|
| **功能** | 为 AI 分析准备结构化的输入数据，确保 AI 只基于真实数据分析 |
| **输入** | 标的 symbol |

| **输出** | 结构化证据包 dict |

#### F-14: 规则型分析引擎
